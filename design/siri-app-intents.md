# Siri and App Intents

Status: design note. Nothing here is built. This needs native code, so it
belongs in the EAS development build phase, not Expo Go.

## Goal

From the mockup:

> "What do I do today?"
> One more round of knee exercises at 6:30, about 10 minutes.

Answered from the patient's own care plan, without opening the app.

## Approach (iOS)

Apple's **App Intents** framework (iOS 16 and later) lets an app offer
actions to Siri, Shortcuts and Spotlight.

1. **A small Swift module** added with the Expo Modules API and a config
   plugin, so it works with `npx expo prebuild` and EAS Build.
2. **Intents:**
   - `WhatsOnTodayIntent`: speaks the remaining sessions and visits for today.
   - `MarkSessionDoneIntent`: marks the next due session done.
3. **App Shortcuts** (`AppShortcutsProvider`) with phrases like "What do I do
   today in Between" so they work with no setup by the patient.

## Sharing data with the intent

Siri can run an intent without starting the JavaScript app, so the intent
can't call into React Native. Instead:

- Whenever the plan or completion log changes, the app writes a small
  "today" summary to an **App Group** shared container (for example,
  `UserDefaults(suiteName:)`) through the native module.
- The intent reads that summary and builds the answer.
- `MarkSessionDoneIntent` writes to the same container; the app imports it
  into the completion log next time it runs, using the existing idempotent
  `markDone`, so nothing is counted twice.

The summary is generated by the same pure functions the Today screen uses
(`agendaFor`, `nextUp`), so Siri and the screen always agree.

## What Siri says

- Next session: "One more round of knee exercises at 6:30, about 10 minutes."
- All done: "You've done all your exercises for today."
- A visit: "Physical therapy visit at 2 PM, 45 minutes."
- Nothing scheduled: "Nothing on your plan today."

## Privacy

- Answers come from data on the phone; nothing is sent to a Between server.
- Set the intents to require the phone to be unlocked, since spoken answers
  mention health activity.

## Same dev build: notification actions

The EAS development build that this needs also fixes the Phase 2 limit:
a background notification handler lets **Mark done** and **In 1 hour** work
without opening the app, even if it was swiped away. Then
`ACTIONS_OPEN_APP` in `src/notifications/native.ts` can go back to `false`.

## Android

Google Assistant has no direct equivalent that an Expo app can add easily.
Options to look at later: App Actions with built-in intents, or a home-screen
widget showing today's next session. Not part of the first version.
